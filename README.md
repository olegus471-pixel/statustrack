# AIMA Tracking Bot

Telegram-бот, который принимает ссылку/код отслеживания процесса AIMA
(`https://contactenos.aima.gov.pt/tracking/<uuid>`), раз в день проверяет
статус через их JSON API и присылает уведомление, когда статус меняется.

## Готово к запуску

Реальный адрес API AIMA уже прописан в коде (`aima_client.py`):

```
GET https://api-contactenos.aima.gov.pt/api/FormTracking/{tracking_id}
```

Ничего в коде редактировать не нужно — переходи сразу к установке.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Настройка

1. Создай бота через [@BotFather](https://t.me/BotFather), получи токен.
2. Экспортируй переменные окружения:

```bash
export BOT_TOKEN="123456:AA...."
export API_URL_TEMPLATE="..."      # см. выше
export API_METHOD="GET"            # или POST
export CHECK_HOUR_UTC=8            # во сколько (UTC) запускать ежедневную проверку
export CHECK_MINUTE_UTC=0
```

## Запуск

```bash
python3 bot.py
```

Бот сразу начнёт принимать сообщения (long polling) и запустит внутренний
планировщик, который раз в сутки (в указанное время UTC) проходит по всем
подписчикам и шлёт уведомление, если статус изменился.

## Как это работает

- Пользователь присылает боту ссылку/UUID → бот делает запрос к API AIMA,
  парсит текущий шаг (`historico`, элемент с `estadoAtual: true`) и
  сохраняет его в SQLite (`aima_bot.sqlite3`) вместе с `chat_id`.
- `/status` — проверить прямо сейчас, не дожидаясь ежедневного цикла.
- `/stop` — **приостановить** ежедневные проверки и уведомления (ссылка остаётся сохранённой).
- `/resume` — возобновить проверки без необходимости заново присылать ссылку.
- `/lang en` / `/lang pt` — язык уведомлений.
- Раз в день `checker.run_daily_check` проходит по всем подпискам,
  сравнивает `tipo` текущего шага с сохранённым, и если он изменился —
  шлёт сообщение и обновляет запись в базе.

## Деплой на Render

Проект уже содержит `render.yaml` — Render прочитает его автоматически
(это называется "Blueprint") и сам создаст нужный сервис с диском.

1. Залей все файлы этой папки в репозиторий на GitHub (можно приватный).
2. На [render.com](https://render.com) → **New** → **Blueprint** → выбери этот репозиторий.
3. Render найдёт `render.yaml` и покажет, что создаст сервис типа **Background Worker**
   с постоянным диском на 1GB — подтверди.
4. Единственное, что попросит вписать вручную — переменную `BOT_TOKEN`
   (значение возьми у @BotFather). Остальные переменные (`DB_PATH` и т.д.)
   уже прописаны в `render.yaml` и подставятся сами.
5. Нажми **Deploy**. Через пару минут бот запустится и будет работать 24/7.

### Почему именно Background Worker, а не Web Service

Наш бот сам постоянно опрашивает Telegram (`long polling`), ему не нужно
принимать входящие HTTP-запросы снаружи — значит, ему не нужен публичный
URL и порт, как у Web Service. Background Worker — как раз для таких
постоянно работающих в фоне процессов.

### Про диск (обязательно для сохранности данных)

Без диска файловая система на Render эфемерна: при каждом передеплое или
перезапуске инстанса файл `aima_bot.sqlite3` будет стираться, и все
подписки пользователей потеряются. `render.yaml` уже подключает диск
на 1GB, смонтированный в `/var/data`, и `DB_PATH` указывает базу именно
туда — так подписки переживут любые перезапуски и обновления кода.

Бесплатный тариф Render (`free`) дисков не поддерживает — поэтому в
`render.yaml` указан план `starter` (самый дешёвый платный, пары долларов
в месяц хватит с запасом для такой нагрузки: один запрос в день на
пользователя).

## Продакшн-соображения

- **Один процесс на чат.** Сейчас у одного `chat_id` может быть только
  один отслеживаемый процесс. Если нужно несколько — таблицу и хендлеры
  придётся немного расширить (составной ключ `chat_id + tracking_id`).
- **Устойчивость к сбоям сайта.** `checker.py` уже не падает целиком,
  если один запрос не удался — ошибка логируется, остальные подписчики
  всё равно проверяются.
- **Частота.** Раз в день — разумно и не похоже на злоупотребление.
  Не имеет смысла проверять чаще: гос. система обновляется не так быстро.
- **Деплой.** Проще всего — небольшой VPS/сервер с `systemd`-юнитом или
  просто `nohup python3 bot.py &`, либо Docker-контейнер, который всегда
  запущен (планировщик встроен в сам процесс, отдельный cron не нужен).
